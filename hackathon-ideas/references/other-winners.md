# Other Winners and Judges (supporting Parth's rules)

Parth's 8 rules are the backbone. These sources add to them; where they seem to conflict, the note says how to reconcile.

## JetBrains - "How to Win a Hackathon: Notes From the Judging Table" (Jun 2026)
https://blog.jetbrains.com/ai/2026/06/how-to-win-a-hackathon-notes-from-the-judging-table/
- Bonnie Xu (OpenAI): don't start from "what's the coolest new tool"; start from "what can I build now that I probably couldn't have built before?" -> same as Parth's Rule 5 (early).
- Bonnie Xu: one clear "this is now possible" moment beats a feature tour -> Rule 4.
- Jono Bacon (Stateshift): make judges share your frustration with the problem; show the solution within ~90 seconds.
- Avi Press (Scarf): state the problem clearly, it isn't obvious. Put the judge in the user's shoes and walk them through.
- Colin Lowenberg (Nebius): the demo is the focus; cut features if it's long. Mock everything you can, pre-fill forms, smooth every flow. Ask sponsors for starter repos.
- Jan-Niklas Wortmann (JetBrains): read the rules and judging goals before writing anything. Use familiar tools and teammates; don't stack new framework + new team + new domain -> Rule 6 (no zero-knowledge domains).

## AngelHack - "Hackathon Tips: What Repeat Winners Do Differently"
https://angelhack.com/blog/hackathon-tips-for-winners/
- A working demo of a smaller idea beats a broken demo of a bigger one. Strong teams lose by scoping too big.
- Read the judging rubric before the problem statement.
- Have a working skeleton by 25% of build time.
- Write the demo script before coding: one-sentence problem, current workaround, demo trigger, "aha" moment, impact close.
- Lock code before the end; record the demo twice; hardcode demo paths; mock external services against Wi-Fi drops and rate limits.
- Talk to sponsor mentors early with sharp questions that show work done.

## Ray Deck - "Lessons from Winning Five Hackathons"
https://sustained.substack.com/p/lessons-from-winning-five-hackathons
- The winning question: **"If I reward this project, will my company look good?"** -> the skill's Gate 11 (sponsor pride).
- Clever sponsor usage can go unrecognized if it's not tied to a story that makes the sponsor look good.
- The demo video is paramount; judges review it and sponsors reuse it in announcements.
- Cut to the bone to ship.

## Reconciling with Parth
- Some guides say "originality doesn't matter, execution does". Parth agrees in Rule 6 (exceptional idea OR exceptional execution with domain knowledge). The skill still bans the obvious AI ideas, because a crowded room makes the same idea look worse no matter how well it's built.
- "Start from a real problem" (JetBrains) vs "don't stress about the problem" (Parth Rule 2): collide sparks first, then check that the idea has a one-line, visible use case (Gate 3 and 4). Both are satisfied.
